Синхронность и асинхронность в JavaScript

назад 
  
    console.log(1);

    setTimeout(function () {
      console.log(3);
    }, 5000);

    console.log(2);
  • 1й console.log попадает в call stack, отрабатывает и уходит
  • setTimeout попадает в call stack и переносится в web apis
  • 2й console.log попадает в call stack, отрабатывает и уходит
  • setTimeout отрабатывает свой таймер в web apis и переносит анонимную функцию (callback) в callback queue (только после очистки стека)
  • после callback queue анонимная функция переходит в call stack и там вызывается 3й console.log, затем событие завершается

Принцип работы стека - последний зашел, первый вышел.

А в очереди - первый зашел, первый вышел

cоответственно из этого следует что в следующем примере будет вывод:

  
    console.log(1);

    setTimeout(function () {
      console.log(3);
    }, 2000);

    setTimeout(function () {
      console.log(4);
    }, 2000);

    console.log(2); 
    
    // 1
    // 2
    // 3
    // 4
